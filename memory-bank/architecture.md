# Архитектура и потоки данных

## Приложение

`main()` в [`src/main.cpp`](../src/main.cpp) загружает `config.json`, запускает watcher, создаёт включённые оверлеи и циклически вызывает `ir_tick()`. Изменение статуса соединения вызывает `handleConfigChange`: оверлеи включаются/выключаются согласно конфигурации и статусу, затем получают `configChanged()`. Смена типа сессии вызывает `sessionChanged()` у каждого оверлея. В обычном режиме оверлеи обновляются примерно каждый кадр (~60 Hz); `General.performance_mode_30hz` распределяет enabled оверлеи по чётным/нечётным кадрам (~30 Hz на оверлей). Обработка сообщений Win32 выполняет горячие клавиши и перемещение/изменение размера.

`Config` ([`src/core/Config.h`](../src/core/Config.h), [`src/core/Config.cpp`](../src/core/Config.cpp)) работает с JSON в рабочем каталоге. Watcher использует `ReadDirectoryChangesW`, сигнализирует об изменении; главный поток перезагружает JSON и передаёт новые параметры оверлеям. Отсутствующие значения вставляются при вызове typed-getter; dirty-конфигурация сохраняется из главного цикла. Перемещение/resize сохраняют позицию и размер через `Overlay::saveWindowPosAndSize()`.

## Графический ресурсный цикл

[`src/core/Overlay.cpp`](../src/core/Overlay.cpp): при включении `Overlay::enable(true)` создаёт окно Win32, D3D11 device, DXGI swap chain, Direct2D factory/render target, DirectComposition target/visual/device, DirectWrite factory и общую кисть. `ComPtr` владеют COM-интерфейсами. При отключении сначала вызывается `onDisable()`, затем сбрасываются графические ресурсы и уничтожается окно. При resize `setWindowPosAndSize()` сначала освобождает render target (ссылку на back buffer), вызывает `ResizeBuffers`, затем заново получает поверхность и создаёт target.

`Overlay::update()` пропускает работу для выключенного окна; рисует прозрачный фон и скруглённую подложку, вызывает виртуальный `onUpdate()`, при необходимости рисует рамку редактирования и затем представляет swap chain. `OverlayDelta::onConfigChanged()` создаёт/обновляет ресурсы и кэширует стили; `onDisable()` сбрасывает `TextCache`.

## Поток данных Delta

Реализация — [`src/overlays/OverlayDelta.h`](../src/overlays/OverlayDelta.h); чистая математика масштабирования/геометрии вынесена в [`src/overlays/delta_logic.h`](../src/overlays/delta_logic.h), тесты — [`tests/test_delta_logic.cpp`](../tests/test_delta_logic.cpp).

1. `onUpdate()` выбирает `ir_LapDeltaToBestLap` + `_OK` для `target=best`, иначе `ir_LapDeltaToSessionBestLap` + `_OK`. `ir_LapDistPct` ограничивается диапазоном [0,1] и отображает дистанцию по горизонтали.
2. `m_delta` — буфер `trace_resolution` (по умолчанию 300, ограничен 16…5000) для долей дистанции круга. При пропущенных вперёд bucket-ах значения интерполируются; повторный/обратный отсчёт обновляет уже пройденный bucket, значение до первой валидной точки игнорируется. Перескок lap distance назад более чем на 0.5 трактуется как граница круга: сначала `captureGhostCandidate()`, затем `resetLap()`.
3. Значение `delta_range_sec` ограничено снизу 0.05 и является **минимальной шкалой (floor)**, не фиксированным диапазоном. При изменении конфигурации `buildLadder()` один раз строит возрастающую лестницу: floor всегда `ladder.front()`, кандидаты `<= floor` удаляются; ближайшая более высокая ступень объединяется с floor, если отношение меньше `STEP_MERGE_RATIO=1.2`. На кадре выбирается наименьшая ступень, покрывающая `max(lapMaxAbs, ghostMaxAbs) * (1 + headroom)`. Ключевой контракт для ревью: **`pickTargetRung()` ищет первую подходящую ступень по возрастанию, но инициализирует результат через `ladder.back()`; если амплитуда с headroom выше вершины лестницы, шкала насыщается верхней ступенью. Нельзя менять на `ladder.front()` — при значении выше вершины это вернёт floor и масштаб неправильно приблизит/обрежет большую амплитуду.** Защитный `yOf()` ограничивает отображение ±текущей шкалой, пока быстрый zoom-out ещё догоняет пик.
4. `easeRange()` приближает текущий диапазон к ступени экспоненциально без wall-clock dt / runtime `exp()`: рост быстрее (`0.09 * rescale_speed`), сжатие медленнее (`0.027 * rescale_speed`); коэффициенты ограничены 1. В режиме 30 Hz используется компенсация `1-(1-k)^2`. Значения пересчитываются на каждом update, включая кадры невалидной delta; пик live-дельты обновляется до выбора масштаба, чтобы реакция началась в том же кадре.

## Контракты reference и validity

Симуляторные CVar объявлены в [`src/iracing/iracing.h`](../src/iracing/iracing.h), используются в `OverlayDelta::onUpdate()` / `captureGhostCandidate()` в [`src/overlays/OverlayDelta.h`](../src/overlays/OverlayDelta.h):

- Целевое время session-best берётся из `CarIdxBestLapTime` для `ir_session.driverCarIdx`, только если индекс в `[0, IR_MAX_CARS)` и время `> 0`; при `-1`/дисконнекте остаётся последняя известная величина. Для target `best` отображается `LapBestLapTime`.
- Не подменять validity-filtered best сырым `LapLastLapTime`: последний включает невалидный круг и мог бы ошибочно сдвинуть header/reference. В source прямо закреплено, что быстрый невалидный круг не обновляет `CarIdxBestLapTime` и reference delta.
- Кандидат ghost захватывается на rollover только при включённом ghost и покрытии почти полного круга (>=90% bucket span, начало близко к нулю). `last` копирует текущий трек; `best`/`session_best` сохраняет только круг, который совпал с validity-filtered best выбранной цели по времени с точностью 1 ms и улучшил прежний best. Поэтому невалидный быстрый lap и внешний best, который водитель сам не проехал, не становятся best ghost и не запускают new-best pulse.
- Ghost-best сохраняет пик абсолютной delta для подбора шкалы; при слиянии его вклад убывает вместе с коэффициентом collapse. Новый session сбрасывает текущую трассу, snapshots, baseline best и pulse/collapse state. Перезагрузка конфига сбрасывает state и удаляет снимки ghost (в том числе при изменении resolution).
- Дельта положительна при потере времени (выше нулевой линии, loss colour); неположительная — gain (ниже линии, gain colour). Section bar строится по `ir_session.sectorStartPct`; сектор считается пройденным только если sampled-диапазон включает обе границы его bucket-ов, иначе отображается серым.

## Пер-frame стоимость и владение

Это наблюдения о текущей реализации, не целевой бюджет производительности:

- Конфигурационно-зависимые ресурсы (DirectWrite formats, dashed ghost stroke style) создаются при `onConfigChanged()`, а не в основном цикле рендеринга. `m_delta` выделяется/обнуляется при обновлении resolution; ghost-векторы копируются только при capture.
- Сбор ladder — только при перезагрузке конфигурации. Максимум trace bucket-ов ограничен 5000. Ghost-best peak вычисляется линейным проходом по снимку при редком capture, не каждый кадр.
- В каждом `OverlayDelta::onUpdate()` остаются проходы по trace для подготовки рендеринга и scale easing. `drawClippedLine` создаёт `ID2D1PathGeometry1` и `ID2D1GeometrySink` для вызова; заполнение знаковых run-ов создаёт отдельный path/sink на run. Эти COM-объекты локальны вызову и отпускаются через `ComPtr`.
- Не помещать построение/sort лестницы, поиск/парсинг config строк, создание stroke style или пересчёт полного ghost-пика в горячий per-frame путь без явной необходимости и измеренного обоснования. Это инженерная рекомендация на основе существующей границы кэширования, а не заявленная гарантия FPS.
